# 通知機能 要件定義書

## 1. 概要

本機能は、管理画面から作成・送信された通知、またはバックエンドで発生した各種イベント通知を、モバイルアプリ利用者へ配信する機能である。

管理画面では通知の受信は行わず、通知の作成・送信、および過去の通知履歴の確認を行う。

モバイルアプリでは Firebase Cloud Messaging（FCM）を利用して通知を受信し、アプリ内の通知一覧から過去の通知を確認できる。

通知内容はバックエンド DB に保存し、モバイルアプリおよび管理画面から通知履歴を取得できるようにする。

モバイルアプリ利用者は、自身に届いた通知の既読・未読状態を確認し、通知を個別または一括で既読にできるようにする。

## 2. 目的

- 管理画面からモバイル利用者へ通知を送信できるようにする
- モバイルアプリ利用者が重要な通知を Push 通知として受け取れるようにする
- モバイルアプリ上で通知履歴を確認できるようにする
- 管理画面上で過去の通知履歴、送信結果を確認できるようにする
- 通知内容をバックエンド DB に保存し、後から確認できるようにする
- FCM による即時配信が失敗した場合でも、通知履歴から内容を確認できるようにする
- モバイルアプリ利用者が未読通知の有無をすぐ把握できるようにする
- 確認済みの通知を既読化し、通知一覧や通知ベルの表示を整理できるようにする

## 3. 利用技術

通知配信には Firebase Cloud Messaging を使用する。

- バックエンド: Firebase Admin SDK
- モバイルアプリ: Firebase Messaging SDK
- 通知配信基盤: Firebase Cloud Messaging
- 通知履歴管理: バックエンド DB
- 管理画面: 通知作成、送信、履歴確認のみを行う

## 4. 通知方式

バックエンドは、通知対象ユーザーに紐づく FCM トークンを取得し、Firebase Cloud Messaging 経由でモバイルアプリへ通知を送信する。

モバイルアプリは Firebase Messaging SDK を利用して通知を受信する。

- アプリ起動中: 画面内通知、通知ベル、通知一覧へ反映する
- バックグラウンド中: OS の Push 通知として表示する
- アプリ未起動時: OS の Push 通知として表示する
- アプリ再表示時: バックエンド API から通知一覧を再取得して整合性を保つ

管理画面は FCM 通知を受信しない。管理画面では以下のみを扱う。

- 通知の作成
- 通知の送信
- 過去の通知履歴の確認
- 送信結果の確認

## 5. 対象通知

本機能で扱う通知は以下を想定する。

- 管理者からのお知らせ
  - 例: メンテナンス案内、重要なお知らせ、利用者への連絡
- 処理完了通知
  - 例: 解析完了、集計完了、変換完了
- エラー通知
  - 例: 処理失敗、外部連携失敗、登録失敗
- 状態変更通知
  - 例: ステータス変更、承認状態変更
- 操作要求通知
  - 例: 確認依頼、承認依頼、再操作依頼

## 6. 機能要件

### 6.1 管理画面向け機能

- 管理画面は通知を作成できる
- 管理画面は通知タイトル、本文、重要度、対象ユーザー、遷移先情報を指定できる
- 管理画面は作成した通知を送信できる
- 管理画面は過去の通知履歴を取得できる
- 管理画面は通知の送信日時、対象ユーザー、送信結果を確認できる
- 管理画面は FCM トークンの取得、登録、Push 通知の受信を行わない

### 6.2 モバイルアプリ向け機能

- モバイルアプリはログイン後に FCM トークンを取得できる
- モバイルアプリは取得した FCM トークンをバックエンドへ登録できる
- バックエンドはユーザー ID と FCM トークンを紐づけて保存できる
- 1 ユーザーに対して複数端末のトークンを保持できる
- バックエンドは特定ユーザー宛に通知を送信できる
- 通知送信時、通知内容を DB に保存する
- モバイルアプリは通知を受信できる
- モバイルアプリは通知一覧を取得できる
- 通知クリック時に指定画面へ遷移できる
- 無効な FCM トークンは送信失敗時に無効化または削除する
- 通知送信に失敗しても、元の業務処理は失敗扱いにしない

### 6.3 既読機能について

- バックエンドは通知ごとに既読状態を保持できる
- バックエンドは通知ごとに既読日時を保持できる
- 新規作成された通知は未読状態で保存する
- モバイルアプリは通知一覧で既読・未読状態を確認できる
- モバイルアプリは未読通知件数を取得できる
- モバイルアプリは指定した通知を既読にできる
- モバイルアプリは自身の通知を一括で既読にできる
- 既読済みの通知に対して再度既読化 API が呼ばれた場合も正常終了する
- 他ユーザー宛の通知を既読化することはできない
- 管理画面では利用者ごとの既読状態を参照できるが、管理画面から既読状態を変更しない

### 6.4 既読・未読の判定

- `read_at` が `NULL` の通知を未読とする
- `read_at` に日時が入っている通知を既読とする
- `is_read` をレスポンスに含める場合は、`read_at IS NOT NULL` から算出する
- 既読化時はサーバー時刻で `read_at` を設定する
- 一度設定された `read_at` は、通常操作では更新しない
- 未読件数はログインユーザー自身の未読通知のみを集計する
- 送信失敗した通知を通知一覧に表示するかどうかは `send_status` の設計に従う。ただし一覧に表示する通知は既読・未読管理の対象とする

## 7. 通知データ項目

通知には以下の情報を含める。

- 通知 ID
- 通知タイプ
- タイトル
- メッセージ
- 対象ユーザー ID
- 関連リソース種別
- 関連リソース ID
- 遷移先 URL
- 重要度
- 作成日時
- 送信日時
- 送信状態
- 既読状態
- 既読日時

通知データ例:

```json
{
  "notification_id": "123",
  "type": "admin_notice",
  "title": "メンテナンスのお知らせ",
  "message": "6月15日 1:00〜3:00 にメンテナンスを実施します。",
  "link_url": "/notifications/123",
  "severity": "info",
  "is_read": false,
  "read_at": null,
  "created_at": "2026-06-09T10:00:00+09:00"
}
```

## 8. API 要件

API のベース URL は以下とする。

```txt
http://localhost:xxxx/api/v1
```

本番環境では、環境ごとのドメインに `/api/v1` を付与する。

### 8.1 モバイル向け API

#### POST /api/v1/notification-tokens

FCM トークンを登録する。

主な利用タイミング:

- ログイン後
- 通知許可取得後
- FCM トークン更新時

#### DELETE /api/v1/notification-tokens

FCM トークンを削除または無効化する。

主な利用タイミング:

- ログアウト時
- 通知解除時
- 端末の利用停止時

#### GET /api/v1/notifications

ログインユーザーの通知一覧を取得する。

主なレスポンス項目:

- 通知 ID
- 通知タイプ
- タイトル
- メッセージ
- 遷移先 URL
- 重要度
- 既読状態
- 既読日時
- 作成日時
- 送信日時

主なクエリパラメータ:

| パラメータ | 必須 | 説明 |
| --- | --- | --- |
| read_status | 任意 | `all` / `read` / `unread`。省略時は `all` |
| limit | 任意 | 取得件数。省略時は 20、最大 100 |
| offset | 任意 | 取得開始位置。省略時は 0 |

#### GET /api/v1/notifications/unread-count

ログインユーザーの未読通知件数を取得する。

レスポンス例:

```json
{
  "unread_count": 3
}
```

#### PATCH /api/v1/notifications/{id}/read

指定した通知を既読にする。

- 対象通知がログインユーザー自身の通知である場合のみ既読化できる
- 対象通知が未読の場合、`read_at` にサーバー時刻を設定する
- 対象通知が既読済みの場合、既存の `read_at` を維持して正常終了する

レスポンス例:

```json
{
  "notification_id": "123",
  "is_read": true,
  "read_at": "2026-06-17T10:00:00+09:00"
}
```

#### PATCH /api/v1/notifications/read-all

ログインユーザーの未読通知をすべて既読にする。

- 対象はログインユーザー自身の未読通知のみとする
- 既読済み通知の `read_at` は更新しない
- 処理件数をレスポンスに含める

レスポンス例:

```json
{
  "updated_count": 3,
  "read_at": "2026-06-17T10:00:00+09:00"
}
```

### 8.2 管理画面向け API

#### POST /api/v1/admin/notifications

管理画面から通知を作成し、対象ユーザーへ送信する。

#### GET /api/v1/admin/notifications

管理画面で過去の通知履歴を取得する。

#### GET /api/v1/admin/notifications/{id}

管理画面で通知の詳細、対象ユーザー、送信結果を取得する。

管理画面向け詳細では、対象ユーザーごとの既読状態と既読日時を参照できる。

### 8.3 エラーレスポンス

既読機能の主なエラーは以下とする。

| ステータス | ケース |
| --- | --- |
| 401 | 未認証 |
| 403 | 他ユーザー宛通知への操作 |
| 404 | 通知が存在しない、または自身が参照できない通知 |
| 400 | 不正なクエリパラメータ |

## 9. データベース設計案

### notification_tokens

| カラム | 説明 |
| --- | --- |
| id | トークン ID |
| user_id | ユーザー ID |
| token | FCM トークン |
| platform | ios / android |
| device_id | 端末識別子 |
| is_active | 有効状態 |
| created_at | 作成日時 |
| updated_at | 更新日時 |
| last_used_at | 最終利用日時 |

### notifications

| カラム | 説明 |
| --- | --- |
| id | 通知 ID |
| user_id | 対象ユーザー ID |
| type | 通知タイプ |
| title | タイトル |
| message | メッセージ |
| link_url | 遷移先 URL |
| resource_type | 関連リソース種別 |
| resource_id | 関連リソース ID |
| severity | 重要度 |
| send_status | 送信状態 |
| sent_at | 送信日時 |
| read_at | 既読日時。未読の場合は NULL |
| created_by | 作成者 ID |
| created_at | 作成日時 |
| updated_at | 更新日時 |

既読状態は `read_at` から算出する。物理カラムとして `is_read` を保持する場合は、`read_at` と不整合が起きないよう更新処理を一元化する。

推奨インデックス:

| インデックス | 用途 |
| --- | --- |
| notifications(user_id, created_at) | 通知一覧取得 |
| notifications(user_id, read_at) | 未読件数取得、未読一覧取得 |

## 10. 非機能要件

- 認証済みユーザーのみ通知トークンを登録できる
- 認証済みユーザーのみ自身の通知一覧を取得できる
- 管理者権限を持つユーザーのみ通知の作成・送信・管理履歴確認ができる
- 他ユーザー宛の通知は一般ユーザーから取得できない
- 他ユーザー宛の通知は一般ユーザーから既読化できない
- Firebase の認証情報は環境変数または Secret で管理する
- 通知送信失敗時はログを出力する
- 無効トークンは検知して無効化する
- 大量通知時は Firebase のバッチ送信を利用する
- 通知送信処理は業務処理と疎結合にする
- 通知履歴は一定期間保存する
- FCM だけに依存せず、アプリ表示時は DB から再取得して整合性を保つ

## 11. MVP 範囲

初期実装では以下を対象とする。

- Firebase Admin SDK の導入
- モバイルアプリ向け FCM トークン登録 API
- モバイルアプリ向け FCM トークン削除 API
- 通知履歴保存
- 管理画面からの通知作成・送信
- 管理画面での通知履歴確認
- ユーザー単位の通知送信
- モバイルアプリでのフォアグラウンド通知受信
- モバイルアプリでのバックグラウンド Push 通知表示
- モバイルアプリでの通知一覧取得
- 既読状態管理
- 未読件数取得
- 個別既読化
- 一括既読化
- 無効トークンの無効化処理

## 12. MVP 対象外・要検討

- 通知カテゴリ別の ON/OFF 設定
- メール通知連携
- 通知テンプレート管理
- 通知重要度ごとの表示制御
- 通知履歴の自動削除
- Slack / LINE / 外部チャットツール連携

## 13. 補足

Firebase Cloud Messaging はリアルタイムに近い通知配信に適しているが、配信保証を完全に担保するものではない。

そのため、本機能では FCM を即時通知の手段として利用しつつ、通知履歴はバックエンド DB で管理する。これにより、通知が一時的に届かなかった場合でも、ユーザーが再度アプリを開いた際に通知内容を確認できる。

## 14. 受け入れ条件

- 新規通知が作成された時点では未読として扱われる
- 通知一覧 API のレスポンスで、各通知の既読状態と既読日時を確認できる
- 未読件数 API で、ログインユーザー自身の未読通知件数を取得できる
- 個別既読 API を実行すると、対象通知の `read_at` が設定され、未読件数が減る
- 既読済み通知に個別既読 API を実行してもエラーにならず、`read_at` は変更されない
- 一括既読 API を実行すると、ログインユーザー自身の未読通知のみが既読になる
- 他ユーザー宛の通知は一覧取得、個別既読、一括既読の対象にならない
- 管理画面では通知ごとの送信結果と既読状態を参照できる
