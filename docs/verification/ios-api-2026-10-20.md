## 実環境の読み取り確認

各環境の接続先は現行のMobile設定とBackend運用Runbookを参照した。
`X-Client-Type: mobile`を付けてcurlでGETした。実ユーザーのTokenは使用していない。

| 確認 | development | staging | production |
| --- | --- | --- | --- |
| GET /health | 200、status=ok | 200、status=ok | 200、status=ok |
| GET /openapi.json | 200、pathsあり | 200、pathsあり | 404 |
| Tokenなし: GET /api/v1/auth/me | 401 UNAUTHORIZED | 401 UNAUTHORIZED | 401 UNAUTHORIZED |
| Tokenなし: GET /api/v1/events | 401 UNAUTHORIZED | 401 UNAUTHORIZED | 401 UNAUTHORIZED |
| Tokenなし: GET /api/v1/me/notifications | 401 UNAUTHORIZED | 401 UNAUTHORIZED | 401 UNAUTHORIZED |
| 無効Token: GET /api/v1/auth/me | 401 INVALID_TOKEN | 401 INVALID_TOKEN | 401 INVALID_TOKEN |

- productionのOpenAPIは非公開。`requireDocsEnabled`の制御と整合する。
- 無効Tokenには合成文字列を使用し、エラー応答にTokenが含まれないことを確認した。
- health成功はD1 Migration適用済み・認証成功・通知配信成功を保証しない。
- 未認証401はアクセス制御の確認であり、認証済みの200応答確認ではない。

再実行時は確認対象環境のoriginを`IOS_API_ORIGIN`へ設定する。実Tokenをコマンドへ直接書かない。

```sh
curl --fail-with-body --silent --show-error "$IOS_API_ORIGIN/health"
curl --silent --show-error --write-out '\n%{http_code}\n' \
  --header 'X-Client-Type: mobile' "$IOS_API_ORIGIN/api/v1/auth/me"
```

## 現在のMobile側の通信対象

以下はMobileのAPI呼び出し箇所とBackend Routeの対応を確認するための一覧であり、実環境での成功記録ではない。

| 機能 | Method / path | Mobile実装 |
| --- | --- | --- |
| Microsoftログイン | GET /api/v1/auth/microsoft/login | AuthApi |
| code交換 | POST /api/v1/auth/microsoft/token | AuthApi |
| プロフィール | GET /api/v1/auth/me | AuthApi |
| プロフィール写真 | GET /api/v1/auth/me/photo | ProfilePhotoRepository |
